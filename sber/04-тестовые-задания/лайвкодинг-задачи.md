# Лайвкодинг-задачи: условие → решение (уровень Сбера)

**Формат Сбера:** 15–30 минут, задача обычно easy/medium, расшаренный экран, диалог с интервьюером. Время дают с запасом — если пойдёшь по неверному пути, успеешь исправить.

Каждая задача: **Задача → Идея → Решение → Сложность → Подвохи**. Сначала закрой решение и попробуй сам, потом сверься.

> Список самых частых алгозадач для лайвкодинга подтверждён подборками (FizzBuzz, Two Sum, Reverse, Palindrome, Binary Search, анаграммы, скобки, Fibonacci, дубликаты, сортировка) — см. источники внизу.

---

## A. Строки

### 1. FizzBuzz (разминка, проверка базы)

**Задача.** Вывести числа от 1 до n. Кратные 3 → "Fizz", кратные 5 → "Buzz", кратные 15 → "FizzBuzz".

**Идея.** Проверяй делимость на 15 **первым** (иначе попадёшь в ветку 3 или 5 и не выведешь FizzBuzz).

**Решение.**
```java
static void fizzBuzz(int n) {
    for (int i = 1; i <= n; i++) {
        if (i % 15 == 0) System.out.println("FizzBuzz");
        else if (i % 3 == 0) System.out.println("Fizz");
        else if (i % 5 == 0) System.out.println("Buzz");
        else System.out.println(i);
    }
}
```
**Сложность.** Время O(n), память O(1).
**Подвохи.** Порядок условий: 15 проверяем до 3 и 5.

---

### 2. Развернуть строку (two pointers)

**Задача.** Развернуть строку: "hello" → "olleh".

**Идея.** Два указателя с концов навстречу, меняем символы местами.

**Решение.**
```java
static String reverse(String s) {
    char[] a = s.toCharArray();
    int l = 0, r = a.length - 1;
    while (l < r) {
        char t = a[l]; a[l] = a[r]; a[r] = t;
        l++; r--;
    }
    return new String(a);
}
```
**Сложность.** Время O(n), память O(n) (массив символов).
**Подвохи.** Спросят «а если эмодзи/суррогатные пары?» — посимвольный разворот их сломает; упомяни, что для Unicode нужен обход по code points.

---

### 3. Палиндром (two pointers)

**Задача.** Проверить, читается ли строка одинаково с обеих сторон.

**Идея.** Два указателя с концов; сравниваем символы.

**Решение.**
```java
static boolean isPalindrome(String s) {
    int l = 0, r = s.length() - 1;
    while (l < r) {
        if (s.charAt(l++) != s.charAt(r--)) return false;
    }
    return true;
}
```
**Сложность.** Время O(n), память O(1).
**Подвохи.** Часто просят «игнорировать регистр и не-буквы» — добавь пропуск символов и `Character.toLowerCase`.

---

### 4. Анаграммы

**Задача.** Проверить, составлены ли две строки из одних и тех же букв ("listen" и "silent").

**Идея.** Два способа: (1) отсортировать обе и сравнить — O(n log n); (2) посчитать частоты букв — O(n).

**Решение (через частоты, быстрее).**
```java
static boolean isAnagram(String a, String b) {
    if (a.length() != b.length()) return false;
    int[] count = new int[26];          // для латиницы в нижнем регистре
    for (int i = 0; i < a.length(); i++) {
        count[a.charAt(i) - 'a']++;
        count[b.charAt(i) - 'a']--;
    }
    for (int c : count) if (c != 0) return false;
    return true;
}
```
**Сложность.** Время O(n), память O(1) (фиксированный массив 26).
**Подвохи.** Для произвольного алфавита/Unicode — `HashMap<Character,Integer>` вместо массива.

---

### 5. Первый неповторяющийся символ

**Задача.** Найти первый символ, встречающийся в строке ровно один раз.

**Идея.** Посчитать частоты, сохраняя порядок появления (`LinkedHashMap`), затем взять первый с count == 1.

**Решение.**
```java
static Optional<Character> firstUnique(String s) {
    Map<Character, Integer> counts = new LinkedHashMap<>(); // помнит порядок вставки
    for (char c : s.toCharArray()) counts.merge(c, 1, Integer::sum);
    return counts.entrySet().stream()
            .filter(e -> e.getValue() == 1)
            .map(Map.Entry::getKey)
            .findFirst();
}
```
**Сложность.** Время O(n), память O(k), k — число различных символов.
**Подвохи.** Обычный `HashMap` потеряет порядок — нужен именно `LinkedHashMap`.

## B. Массивы, поиск, хеши

### 6. Two Sum (HashMap, O(n))

**Задача.** В массиве найти индексы двух чисел, дающих в сумме target.

**Идея.** Идём по массиву, для каждого числа ищем «дополнение» (target − число) в уже виденных. HashMap даёт поиск за O(1).

**Решение.**
```java
static int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> seen = new HashMap<>();   // значение -> индекс
    for (int i = 0; i < nums.length; i++) {
        Integer j = seen.get(target - nums[i]);
        if (j != null) return new int[]{j, i};
        seen.put(nums[i], i);
    }
    throw new IllegalArgumentException("нет решения");
}
```
**Сложность.** Время O(n), память O(n).
**Подвохи.** Наивное решение «два вложенных цикла» — O(n²); интервьюер ждёт именно хеш-вариант. Уточни: что если решений несколько / нет решения.

---

### 7. Есть ли дубликаты в массиве

**Задача.** Определить, есть ли в массиве повторяющиеся элементы.

**Идея.** Складываем в `HashSet`; если `add` вернул false — дубликат.

**Решение.**
```java
static boolean hasDuplicates(int[] a) {
    Set<Integer> seen = new HashSet<>();
    for (int x : a) {
        if (!seen.add(x)) return true;   // add вернул false → уже было
    }
    return false;
}
```
**Сложность.** Время O(n), память O(n).
**Подвохи.** Можно за O(1) памяти, отсортировав массив (O(n log n)) и сравнив соседей — обсуди trade-off память vs время.

---

### 8. Бинарный поиск

**Задача.** Найти индекс элемента в **отсортированном** массиве (или −1).

**Идея.** Делим диапазон пополам, сравниваем со средним.

**Решение.**
```java
static int binarySearch(int[] a, int target) {
    int lo = 0, hi = a.length - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;       // не (lo+hi)/2 — защита от переполнения
        if (a[mid] == target) return mid;
        if (a[mid] < target) lo = mid + 1;
        else hi = mid - 1;
    }
    return -1;
}
```
**Сложность.** Время O(log n), память O(1).
**Подвохи.** Классическая ошибка `(lo + hi) / 2` — переполнение int на больших массивах. Граница цикла `lo <= hi`.

### 9. Частота слов: топ-3 (коллекции + Stream)

**Задача.** Вернуть 3 самых частых слова в тексте.

**Идея.** Разбить на слова → посчитать частоты (`groupingBy + counting`) → отсортировать по убыванию → взять 3.

**Решение.**
```java
Map<String, Long> freq = Arrays.stream(text.toLowerCase().split("\\W+"))
        .filter(w -> !w.isBlank())
        .collect(Collectors.groupingBy(w -> w, Collectors.counting()));

List<String> top3 = freq.entrySet().stream()
        .sorted(Map.Entry.<String, Long>comparingByValue().reversed())
        .limit(3)
        .map(Map.Entry::getKey)
        .toList();
```
**Сложность.** Время O(n + k log k), память O(k), k — число уникальных слов.
**Подвохи.** Для очень больших k эффективнее куча (`PriorityQueue`) размера 3, чем полная сортировка.

## C. Алгоритмы

### 10. Сбалансированные скобки (стек)

**Задача.** Проверить корректность скобок `()[]{}`.

**Идея.** Открывающую кладём в стек; на закрывающую снимаем верх и проверяем пару.

**Решение.**
```java
static boolean isBalanced(String s) {
    Deque<Character> stack = new ArrayDeque<>();
    Map<Character, Character> pairs = Map.of(')', '(', ']', '[', '}', '{');
    for (char c : s.toCharArray()) {
        if (pairs.containsValue(c)) stack.push(c);          // открывающая
        else if (pairs.containsKey(c)) {                    // закрывающая
            if (stack.isEmpty() || stack.pop() != pairs.get(c)) return false;
        }
    }
    return stack.isEmpty();   // в конце стек должен быть пуст
}
```
**Сложность.** Время O(n), память O(n).
**Подвохи.** Не забудь финальную проверку `stack.isEmpty()` (для случая "((").

---

### 11. Максимальная сумма подмассива (алгоритм Кадане)

**Задача.** Найти максимальную сумму непрерывного подмассива.

**Идея.** Идём по массиву; на каждом шаге решаем: продолжить текущий подмассив или начать новый с этого элемента.

**Решение.**
```java
static int maxSubArray(int[] a) {
    int best = a[0], cur = a[0];
    for (int i = 1; i < a.length; i++) {
        cur = Math.max(a[i], cur + a[i]);   // продолжить или начать заново
        best = Math.max(best, cur);
    }
    return best;
}
```
**Сложность.** Время O(n), память O(1).
**Подвохи.** Инициализируй первым элементом, а не нулём — иначе сломается на массиве из одних отрицательных чисел.

---

### 12. N-е число Фибоначчи (итеративно)

**Задача.** Найти n-е число Фибоначчи.

**Идея.** Рекурсия без мемоизации экспоненциальна (O(2ⁿ)) — пиши итеративно за O(n), храня два предыдущих.

**Решение.**
```java
static long fib(int n) {
    if (n < 2) return n;
    long a = 0, b = 1;
    for (int i = 2; i <= n; i++) {
        long next = a + b;
        a = b; b = next;
    }
    return b;
}
```
**Сложность.** Время O(n), память O(1).
**Подвохи.** `int` переполнится уже на fib(47) — используй `long`. Назови, что наивная рекурсия — O(2ⁿ).

## D. Stream API (любимое у Сбера)

### 13. Группировка: средняя зарплата по отделам

**Задача.** Посчитать среднюю зарплату по каждому отделу (деньги — `BigDecimal`).

**Идея.** `groupingBy` по отделу + свести список зарплат к среднему.

**Решение.**
```java
record Employee(String name, String dept, BigDecimal salary) {}

Map<String, BigDecimal> avgByDept = employees.stream()
    .collect(Collectors.groupingBy(Employee::dept,
        Collectors.collectingAndThen(
            Collectors.toList(),
            list -> list.stream()
                .map(Employee::salary)
                .reduce(BigDecimal.ZERO, BigDecimal::add)
                .divide(BigDecimal.valueOf(list.size()), 2, RoundingMode.HALF_UP))));
```
**Сложность.** Время O(n), память O(n).
**Подвох-вопрос интервьюера.** «Почему BigDecimal, а не double для денег?» → двоичный double не представляет 0.1 точно (`0.1 + 0.2 != 0.3`); в банке только `BigDecimal` или целые копейки в `long`.

## E. Многопоточность

### 14. Producer-Consumer (очередь)

**Задача.** Реализовать «производитель кладёт задачи, потребитель забирает», с ограничением буфера.

**Идея.** Готовая `BlockingQueue` сама блокирует на полной/пустой очереди — не нужно писать wait/notify руками.

**Решение.**
```java
BlockingQueue<Task> queue = new ArrayBlockingQueue<>(100);

// producer
queue.put(task);          // блокируется, если очередь заполнена

// consumer
Task t = queue.take();    // блокируется, если очередь пуста
```
**Сложность.** put/take — O(1).
**Подвохи.** Будь готов написать и «вручную» на `wait/notify` (в цикле `while`!) — проверяют понимание мониторов. См. [многопоточность, вопрос 7](../03-вопросы-собеседований/ответы/ответы-многопоточность.md).

### 15. Потокобезопасный Singleton (double-checked locking)

**Задача.** Сделать «ленивый» синглтон, безопасный в многопоточке.

**Идея.** Двойная проверка + `volatile` (иначе другой поток увидит недостроенный объект).

**Решение.**
```java
class Config {
    private static volatile Config instance;   // volatile обязателен!
    private Config() {}
    static Config getInstance() {
        if (instance == null) {
            synchronized (Config.class) {
                if (instance == null) instance = new Config();
            }
        }
        return instance;
    }
}
```
**Подвохи.** Назови более простые альтернативы: **holder idiom** (ленивость через загрузку вложенного класса) и **enum-синглтон**. Разбор, почему нужен volatile, — [многопоточность, вопрос 21](../03-вопросы-собеседований/ответы/ответы-многопоточность.md).

## F. «Что выведет код?» — ловушки

### 16. Классические подвохи

**Задача.** Сказать, что выведет код и почему.

```java
Integer a = 127, b = 127;
Integer c = 128, d = 128;
System.out.println(a == b);  // true  — кеш Integer −128..127, один объект
System.out.println(c == d);  // false — вне кеша, разные объекты

List<Integer> list = new ArrayList<>(List.of(1, 2, 3));
for (Integer x : list) {
    if (x == 2) list.remove(x);   // ❌ ConcurrentModificationException
}
// правильно: list.removeIf(x -> x == 2);

System.out.println(0.1 + 0.2 == 0.3);  // false — двоичная арифметика double
```

**Что проверяют.** Кеш `Integer`, fail-fast итераторы, неточность `double`. Разбор — [Java Core, вопросы 8, 22, 13](../03-вопросы-собеседований/ответы/ответы-java-core.md).

## Чек-лист поведения на лайвкодинге

1. **Повтори условие** своими словами, уточни граничные случаи (null, пустой ввод, отрицательные, дубликаты).
2. **Проговори план** до написания кода.
3. **Пиши читаемо:** нормальные имена, без однобуквенных переменных (кроме индексов цикла).
4. **Сам прогони** на примере: обычный случай + граничный.
5. **Назови сложность** по времени и памяти (Big-O) — почти всегда спрашивают.
6. **Застрял — говори вслух.** Интервьюеры Сбера ведут диалог и помогают, ценят ход мыслей.
