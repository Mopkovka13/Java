# Фирменная задача Сбера: код-ревью «Найди 8 багов»

**Супер-хит сберовских собеседований** ([источник](https://habr.com/ru/articles/995600/)): дают класс `Person` с Serializable, Externalizable, clone() и JAXB-аннотациями — нужно найти восемь багов. Проверяют знание **контрактов языка** и внимательность: код компилируется, тесты проходят, но в проде данные тихо перепутаются. «В банковском софте такие баги стоят денег».

## Реконструкция задачи (тренируйся на ней)

```java
@XmlRootElement
public class Person implements Externalizable, Serializable {

    private String name;
    private String phone;
    private String address;
    private Integer age;

    public Person(String name, String phone, String address, Integer age) {
        this.name = name;
        this.phone = phone;
        this.address = address;
        this.age = age;
    }

    @Override
    public void writeExternal(ObjectOutput out) throws IOException {
        out.writeObject(name);
        out.writeObject(phone);
        out.writeObject(address);
        out.writeObject(age);
    }

    @Override
    public void readExternal(ObjectInput in) throws IOException, ClassNotFoundException {
        this.name = (String) in.readObject();
        this.address = (String) in.readObject();   // !
        this.phone = (String) in.readObject();     // !
        this.age = (Integer) in.readObject();
    }

    @Override
    public Person clone() {
        return (Person) super.clone();
    }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof Person)) return false;
        Person p = (Person) o;
        return name.equals(p.name) && age == p.age;
    }

    @Override
    public int hashCode() {
        return 1;
    }
}
```

## Разбор багов (минимум 8)

1. **Нет public-конструктора без аргументов** — `Externalizable` требует его для десериализации: упадёт с `InvalidClassException`. (JAXB тоже требует no-arg конструктор.)
2. **Перепутан порядок полей в readExternal** — phone и address записаны в одном порядке, читаются в другом. Исключения НЕ будет (оба String) — данные **молча** перемешаются. Самый дорогой баг.
3. **clone() без implements Cloneable** — `super.clone()` бросит `CloneNotSupportedException` в рантайме.
4. **clone() не объявляет/не обрабатывает CloneNotSupportedException** — и вообще: super.clone() возвращает Object, без Cloneable это не скомпилируется корректно / упадёт; копирующий конструктор надёжнее.
5. **hashCode() возвращает 1** — контракт формально соблюдён, но HashMap деградирует: все объекты в одном бакете → O(n) (или дерево). Производительность умирает молча.
6. **equals использует `age == p.age` для Integer** — сравнение ссылок: для age > 127 (вне кеша Integer) равные значения дадут false.
7. **equals и hashCode несогласованы** — equals учитывает name и age, hashCode — ничего; равные объекты обязаны иметь равный hashCode (тут «спасает» только константа, что само по себе баг производительности; если бы hashCode считался по phone — был бы прямой брейк контракта).
8. **`instanceof` в equals нарушает симметричность при наследовании** (спорный, но любимый пункт: подкласс с расширенным equals сломает симметрию; обсуди getClass() vs instanceof).
9. **Externalizable + Serializable одновременно** — Externalizable уже расширяет Serializable; дублирование сигнализирует непонимание. При наличии обоих используется Externalizable.
10. **NPE в equals** — `name.equals(...)` упадёт, если name == null; нужен Objects.equals.
11. **Нет serialVersionUID** — при изменении класса десериализация старых данных сломается непредсказуемо.
12. **Мутабельный класс с equals/hashCode** — объект-ключ в HashMap «потеряется» после изменения поля.

> На собеседовании называй баг → **последствие в проде** → как исправить. Формат «что-почему-как чинить» — именно то, что оценивают.

## Как тренироваться

1. Закрой разбор, найди баги сам, потом сверься.
2. Напиши класс правильно: иммутабельный, с Objects.equals/hash, без clone (копирующий конструктор), record для DTO.
3. Повтори контракты: equals/hashCode, Comparable, Serializable/Externalizable, Cloneable — это ядро задачи.
4. Аналогичный формат для Spring: код сервиса с багами (@Transactional на private, self-invocation, инжекция через поле, незакрытые ресурсы, SimpleDateFormat в поле синглтона, каталог багов — в `../03-вопросы-собеседований/spring.md`).
