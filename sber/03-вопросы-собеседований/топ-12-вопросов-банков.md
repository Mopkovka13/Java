# Топ-12 вопросов банковских Java-собеседований (включая Сбер)

По анализу 247 Java-собеседований в банках РФ ([Хабр](https://habr.com/ru/articles/1043906/)) — эти вопросы встречаются в 80% случаев. Цифра в скобках — на скольких интервью спрашивали.

> Главный вывод статьи: «Если ответить на все 12 вопросов с примерами кода — пройдёшь Middle почти в любом русском банке». Сбер требует **глубины** по 3–4 темам, а не поверхностности по 30.

## 1. Контракт equals() и hashCode() (41)
- Рефлексивность, симметричность, транзитивность, консистентность, сравнение с null.
- Связь: равные объекты → одинаковый hashCode (обратное неверно).
- Что сломается в HashMap, если переопределить только equals.

## 2. Внутреннее устройство HashMap (38)
- Массив бакетов, хеширование, обработка коллизий цепочками.
- Java 8+: цепочка → красно-чёрное дерево при 8 элементах (TREEIFY_THRESHOLD), обратно при 6.
- load factor 0.75, resize ×2, почему capacity — степень двойки.

## 3. Уровни изоляции транзакций и MVCC (32)
- READ UNCOMMITTED / READ COMMITTED / REPEATABLE READ / SERIALIZABLE.
- Аномалии: dirty read, non-repeatable read, phantom read.
- Особенности PostgreSQL: READ UNCOMMITTED ведёт себя как READ COMMITTED; MVCC — версии строк вместо блокировок чтения.

## 4. Проблема N+1 в Hibernate (28)
- Что это: 1 запрос за списком + N запросов за связями.
- Решения: `JOIN FETCH` в JPQL, `@EntityGraph`, `@BatchSize` / `default_batch_fetch_size`, DTO-проекции.

## 5. @Transactional propagation (27)
- Все 7 значений: REQUIRED, REQUIRES_NEW, NESTED, SUPPORTS, NOT_SUPPORTED, MANDATORY, NEVER.
- Особенно NESTED — работает через savepoint, отличие от REQUIRES_NEW.

## 6. Kafka: partition key и порядок сообщений (24)
- Порядок гарантируется **только внутри партиции**.
- Ключ → партиция (hash). Сообщения одного клиента/счёта — с одним ключом.
- Что будет при увеличении числа партиций (перераспределение ключей).

## 7. ⚠️ Self-invocation в @Transactional (31) — валит 9 из 10
- Spring-прокси перехватывает только **внешние** вызовы. `this.methodB()` изнутри класса — транзакция/аннотация НЕ сработает.
- Решения: self-injection через `@Lazy`, вынести метод в отдельный сервис, AspectJ-режим, `TransactionTemplate`.
- Подробный разбор: см. `spring.md`.

## 8. Code Review Spring-сервиса (21)
- Дают код сервиса — найти 8+ проблем (транзакции, инжекция, исключения, ресурсы, конкурентность).
- Фирменный формат Сбера — см. `../04-тестовые-задания/код-ревью-8-багов.md`.

## 9. CPU throttling в Kubernetes (14)
- Почему инстанс «тормозит» при CPU limits: CFS-квоты, троттлинг при достижении limit.
- Диагностика: метрики container_cpu_cfs_throttled_*, рекомендация — осторожно с CPU limits для JVM, правильно задавать -XX:ActiveProcessorCount.

## 10. SELECT FOR UPDATE и lost update (13)
- Проблема lost update при конкурентном чтении-изменении-записи.
- Пессимистичная блокировка: `SELECT ... FOR UPDATE`; альтернатива — оптимистичная (`@Version`).

## 11. Логическая задача (мост и фонарик) (5, ВТБ Senior)
- Четверо переходят мост (1, 2, 5, 10 мин), фонарик один, идут по двое. Ответ: **17 минут** (1+2 → 1 ← → 5+10 → 2 ← → 1+2).
- В Сбере логические задачи редки, но будь готов.

## 12. STAR-рассказ про прод-инцидент (11, Senior)
- Подготовь заранее: Situation → Task → Action → Result.
- Хорошая история: ты нашёл причину, починил, добавил мониторинг/процесс, чтобы не повторилось. Честно про свою ошибку — плюс, скрывание — минус.
