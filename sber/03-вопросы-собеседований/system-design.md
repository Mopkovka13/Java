# System Design — секция для Senior / Tech Lead (Сбер)

> 📝 Самопроверка: краткие ответы (12 концептуальных вопросов + 4 скелета решений типовых задач) — в [ответы/ответы-system-design.md](ответы/ответы-system-design.md).

Формулировка Сбера: «Спроектируем систему, удовлетворяющую функциональным и нефункциональным требованиям». Для Middle секции обычно нет, но вопросы по архитектуре встроены в техническую часть.

Рекомендованная Сбером книга: **«Designing Data-Intensive Applications»** (Martin Kleppmann).

## Фреймворк ответа (45–60 минут)

1. **Требования (5–10 мин)**: функциональные + нефункциональные (RPS, латентность, объём данных, доступность 99.9%?). Задавай вопросы — это оценивается.
2. **Оценка нагрузки**: пользователи → RPS → пиковые нагрузки → объём хранения. Порядки, не точность.
3. **High-level design**: клиенты → LB → API Gateway → сервисы → БД/кеш/очередь. Рисуй.
4. **Глубокое погружение**: схема данных, ключевые потоки, выбор технологий с обоснованием.
5. **Узкие места**: шардирование, репликация, кеши, деградация, мониторинг.

## Темы, которые нужно уверенно держать

- Масштабирование: вертикальное vs горизонтальное, stateless-сервисы, балансировка.
- БД: репликация (sync/async, lag), шардирование (по какому ключу, resharding), индексы.
- Кеширование: cache-aside / write-through, инвалидация, TTL, stampede (locks/jitter).
- Очереди: Kafka для развязки и сглаживания пиков; exactly-once vs идемпотентность.
- Консистентность: CAP, strong vs eventual, распределённые транзакции (Saga, Outbox), консенсус на словах.
- Отказоустойчивость: ретраи с backoff, circuit breaker, таймауты, graceful degradation, multi-AZ.
- Безопасность: аутентификация (OAuth2/JWT), rate limiting, идемпотентные платежи.
- Наблюдаемость: метрики, логи, трейсинг, алерты, SLO/SLI.

## Типовые задачи (банковский уклон — вероятен в Сбере)

1. **Система платежей / переводов** — идемпотентность, exactly-once, Saga, ledger-таблицы, защита от double-spend (SELECT FOR UPDATE / optimistic), аудит.
2. **Уведомления (push/sms/email)** — очереди, приоритеты, ретраи, DLQ, дедупликация.
3. **Сокращатель ссылок** — классика: генерация ключей, кеш, редирект, аналитика.
4. **Лента операций / выписка** — пагинация (cursor), горячие/холодные данные, агрегаты.
5. **Rate limiter** — token bucket / sliding window, распределённый вариант на Redis.
6. **Highload-каталог (СберМаркет-стиль)** — поиск, кеши, инвалидация остатков.

## Чем готовиться

- Kleppmann «Designing Data-Intensive Applications» — главы про репликацию, партиционирование, транзакции, консистентность.
- Alex Xu «System Design Interview» (тома 1–2) — структура ответа и разборы.
- [system-design-primer (GitHub)](https://github.com/donnemartin/system-design-primer) — бесплатный конспект.
