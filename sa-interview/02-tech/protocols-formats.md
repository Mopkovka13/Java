## HTTP

### 🟢 Вопрос: Что такое HTTP? Из чего состоит запрос/ответ?

**HTTP** — протокол передачи данных «запрос-ответ» между клиентом и сервером (поверх TCP).

**Запрос:** метод + URL + заголовки (headers) + тело (body).
**Ответ:** статус-код + заголовки + тело.

Важные заголовки: `Content-Type`, `Authorization`, `Accept`, `Cache-Control`, `User-Agent`, `Cookie`.

### 🟡 Вопрос: Чем HTTP отличается от HTTPS?

HTTPS = HTTP + шифрование TLS/SSL. Данные шифруются, есть проверка подлинности сервера сертификатом. Защита от перехвата (MITM). Для любых чувствительных данных — только HTTPS.

### 🟡 Вопрос: Чем HTTP/2 лучше HTTP/1.1?

Мультиплексирование (много запросов по одному соединению), бинарный протокол, сжатие заголовков, server push. Быстрее, меньше задержек. HTTP/3 — поверх QUIC (UDP).

### 🟡 Вопрос: Что такое CORS?

**Cross-Origin Resource Sharing** — механизм, разрешающий браузеру запросы к другому домену. Сервер заголовками (`Access-Control-Allow-Origin`) указывает, каким источникам можно. Защита от несанкционированных кросс-доменных запросов.

## Форматы данных

### 🟢 Вопрос: Чем JSON отличается от XML?

| | JSON | XML |
|---|---|---|
| Читаемость | компактнее | многословнее |
| Типы | есть (число, bool, null) | всё текст |
| Схема | JSON Schema | XSD, DTD |
| Атрибуты | нет | есть |
| Где | REST, веб | SOAP, legacy, документы |

```json
{ "id": 1, "name": "Иван", "active": true }
```
```xml
<user><id>1</id><name>Иван</name><active>true</active></user>
```

### 🟡 Вопрос: Какие ещё форматы знаешь?

- **YAML** — конфиги, OpenAPI (читаемый, отступы).
- **Protobuf** — бинарный, для gRPC (компактный, быстрый).
- **CSV** — табличные данные, выгрузки.
- **Avro/Parquet** — big data, Kafka-схемы.

## Аутентификация и авторизация

### 🟢 Вопрос: Чем аутентификация отличается от авторизации?

- **Аутентификация (Authentication)** — «кто ты?» (проверка личности: логин/пароль, токен).
- **Авторизация (Authorization)** — «что тебе можно?» (проверка прав доступа).

### 🟡 Вопрос: Какие способы аутентификации в API знаешь?

- **Basic Auth** — логин:пароль в base64 (только по HTTPS, слабый).
- **API Key** — ключ в заголовке.
- **Session/Cookie** — сессия на сервере, id в куке (stateful).
- **Token-based (JWT)** — токен в заголовке (stateless).
- **OAuth 2.0 / OpenID Connect** — делегированный доступ.
- **mTLS** — взаимная аутентификация по сертификатам (банки, межсервис).

### 🟡 Вопрос: Что такое JWT?

**JWT (JSON Web Token)** — самодостаточный токен из 3 частей через точку: **Header.Payload.Signature** (base64).
- **Header** — алгоритм подписи.
- **Payload (claims)** — данные (id пользователя, роли, срок `exp`).
- **Signature** — подпись для проверки целостности.

Плюс: **stateless** — сервер не хранит сессию, проверяет подпись. Минус: сложно отозвать до истечения (нужны короткий TTL + refresh-токен, blacklist). Payload **не шифруется**, только подписан — не клади туда секреты.

### 🟡 Вопрос: Как работает OAuth 2.0?

Протокол **делегированной авторизации** — даёт стороннему приложению доступ к ресурсам без передачи пароля. Роли: Resource Owner (пользователь), Client (приложение), Authorization Server, Resource Server.

Основной поток **Authorization Code:**
1. Пользователь жмёт «Войти через X».
2. Редирект на Authorization Server, пользователь логинится и даёт согласие.
3. Возвращается **authorization code**.
4. Client меняет code на **access token** (и refresh token).
5. Client обращается к API с access token.

**OpenID Connect (OIDC)** — надстройка над OAuth2 для аутентификации (выдаёт **id_token** с данными пользователя).

### 🔴 Вопрос: Чем access token отличается от refresh token?

- **Access token** — короткоживущий (минуты), используется для доступа к API.
- **Refresh token** — долгоживущий, используется для получения нового access token без повторного логина. Хранится надёжнее.

### 🟡 Вопрос: Что такое RBAC и ABAC?

- **RBAC (Role-Based)** — доступ по ролям (admin, manager, user). Просто, распространено.
- **ABAC (Attribute-Based)** — доступ по атрибутам (отдел, время, регион, сумма). Гибче, сложнее.

## Безопасность (база для СА)

### 🟡 Вопрос: Какие угрозы безопасности знаешь (OWASP)?

- **SQL Injection** — внедрение SQL → параметризованные запросы.
- **XSS** — внедрение скриптов → экранирование вывода.
- **CSRF** — подделка запроса → CSRF-токены.
- **Broken Authentication / Access Control** — слабая аутентификация/права.
- **Sensitive Data Exposure** — утечка данных → шифрование.

### 🟡 Вопрос: Что такое шифрование в покое и в движении?

- **In transit (в движении)** — данные шифруются при передаче (TLS/HTTPS).
- **At rest (в покое)** — данные шифруются в хранилище (БД, диски). В банках — обязательно для ПДн и платёжных данных.

### 🟡 Вопрос: Что такое ПДн и почему это важно (РФ)?

**Персональные данные** регулируются **152-ФЗ**. Требования: согласие на обработку, хранение на территории РФ, защита, ограничение доступа. Для платёжных карт — стандарт **PCI DSS**. Аналитик должен учитывать это в требованиях (маскирование, шифрование, аудит доступа).

### 🟡 Вопрос: Что такое маскирование данных?

Скрытие части чувствительных данных (карта `**** **** **** 1234`, телефон `+7 *** *** 12 34`). Применяют в UI, логах, тестовых средах. Частое требование в банковских системах.

## Чит-лист

- Аутентификация = кто ты, авторизация = что можно.
- JWT = stateless токен (Header.Payload.Signature), payload только подписан.
- OAuth2 = делегированный доступ, OIDC = аутентификация поверх.
- access token короткий, refresh — длинный.
- HTTPS всегда; шифрование at rest + in transit.
- РФ: 152-ФЗ (ПДн), PCI DSS (карты).
