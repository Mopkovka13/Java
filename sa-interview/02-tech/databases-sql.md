## Типы баз данных

### 🟢 Вопрос: Чем отличаются SQL и NoSQL базы?

| | SQL (реляционные) | NoSQL |
|---|---|---|
| Структура | Таблицы, жёсткая схема | Гибкая схема |
| Связи | Через FK, JOIN | Денормализация |
| Масштабирование | Вертикальное (в основном) | Горизонтальное |
| Транзакции | ACID | Чаще BASE |
| Примеры | PostgreSQL, Oracle, MS SQL, MySQL | MongoDB, Redis, Cassandra, Elasticsearch |
| Когда | Сложные связи, целостность важна (банки, ERP) | Большие объёмы, гибкость, скорость |

### 🟡 Вопрос: Какие виды NoSQL бывают?

- **Документные** (MongoDB) — JSON-документы.
- **Ключ-значение** (Redis) — кэш, сессии.
- **Колоночные** (Cassandra, ClickHouse) — аналитика, большие объёмы.
- **Графовые** (Neo4j) — связи (соцсети, антифрод-графы).

## Нормализация

### 🟢 Вопрос: Что такое нормализация? Расскажи про нормальные формы.

**Нормализация** — устранение избыточности данных и аномалий через разбиение таблиц.

- **1НФ:** все значения атомарны (нет списков в ячейке), есть первичный ключ. ❌ «телефоны: 111, 222» → ✔ отдельные строки.
- **2НФ:** 1НФ + нет частичной зависимости от части составного ключа (все неключевые атрибуты зависят от **всего** ключа).
- **3НФ:** 2НФ + нет транзитивных зависимостей (неключевой атрибут не зависит от другого неключевого). Пример нарушения: в таблице заказа хранится `city` и `region`, где region зависит от city → выносим в справочник.

На практике обычно доводят до 3НФ. Дальше — BCNF, 4НФ, 5НФ (упоминают редко).

### 🟡 Вопрос: Что такое денормализация и зачем она?

Намеренное добавление избыточности (дублирование данных) ради **скорости чтения** — меньше JOIN-ов. Минус: сложнее поддерживать целостность при изменениях. Применяют в аналитике, отчётах, хранилищах, высоконагруженном чтении.

## Ключи и связи

### 🟢 Вопрос: Какие бывают ключи?

- **Первичный (Primary Key)** — уникально идентифицирует строку, NOT NULL, уникален.
- **Внешний (Foreign Key)** — ссылка на PK другой таблицы, обеспечивает ссылочную целостность.
- **Уникальный (Unique)** — уникальность значений, но допускает NULL.
- **Составной (Composite)** — ключ из нескольких полей.
- **Суррогатный** (auto-increment id) vs **естественный** (натуральный, напр. ИНН).

### 🟡 Вопрос: Что делает ON DELETE CASCADE?

При удалении родительской записи автоматически удаляются связанные дочерние. Альтернативы: `RESTRICT` (запретить, если есть связанные), `SET NULL`, `NO ACTION`.

## SQL-запросы

### 🟢 Вопрос: Какие виды JOIN ты знаешь?

- **INNER JOIN** — только совпадающие строки в обеих таблицах.
- **LEFT JOIN** — все из левой + совпадения из правой (нет совпадения → NULL).
- **RIGHT JOIN** — все из правой + совпадения из левой.
- **FULL OUTER JOIN** — все из обеих, NULL где нет пары.
- **CROSS JOIN** — декартово произведение.
- **SELF JOIN** — таблица сама с собой (иерархии: сотрудник-руководитель).

```
INNER:  A ∩ B        LEFT:  A + (A∩B)
RIGHT:  B + (A∩B)    FULL:  A ∪ B
```

### 🟢 Вопрос: В каком порядке выполняется SQL-запрос?

Логический порядок (не как пишется!):
```
1. FROM / JOIN      — источники данных
2. WHERE            — фильтрация строк
3. GROUP BY         — группировка
4. HAVING           — фильтрация групп
5. SELECT           — выбор колонок
6. DISTINCT
7. ORDER BY         — сортировка
8. LIMIT / OFFSET   — ограничение
```
Поэтому в `WHERE` нельзя использовать алиас из `SELECT`, а в `HAVING` — можно агрегаты.

### 🟢 Вопрос: Чем WHERE отличается от HAVING?

- **WHERE** фильтрует **строки до** группировки, не работает с агрегатами.
- **HAVING** фильтрует **группы после** GROUP BY, работает с агрегатами (`HAVING COUNT(*) > 5`).

### 🟡 Вопрос: Какие агрегатные функции знаешь?

`COUNT()`, `SUM()`, `AVG()`, `MIN()`, `MAX()`. Важно: `COUNT(*)` считает все строки, `COUNT(col)` — только не-NULL значения. Агрегаты игнорируют NULL.

### 🟡 Вопрос: Что такое подзапрос? Чем коррелированный отличается от обычного?

- **Обычный подзапрос** выполняется один раз, результат используется внешним запросом.
- **Коррелированный** ссылается на внешний запрос и выполняется для каждой строки (медленнее).

```sql
-- коррелированный: клиенты с заказами
SELECT c.name FROM clients c
WHERE EXISTS (SELECT 1 FROM orders o WHERE o.client_id = c.id);
```

### 🟡 Вопрос: Что такое CTE и оконные функции?

**CTE (WITH)** — именованный временный результат, улучшает читаемость, поддерживает рекурсию:
```sql
WITH top_clients AS (
  SELECT client_id, SUM(amount) total FROM orders GROUP BY client_id
)
SELECT * FROM top_clients WHERE total > 100000;
```

**Оконные функции** — вычисления по «окну» строк без схлопывания (в отличие от GROUP BY):
```sql
SELECT name, department, salary,
  RANK() OVER (PARTITION BY department ORDER BY salary DESC) AS rnk
FROM employees;
```
Функции: `ROW_NUMBER()`, `RANK()`, `DENSE_RANK()`, `LAG()/LEAD()`, `SUM() OVER(...)`. Частый вопрос: «выбрать N-ю зарплату» / «топ по группе».

### 🟡 Вопрос: Чем UNION отличается от UNION ALL?

`UNION` объединяет и **убирает дубликаты** (медленнее), `UNION ALL` — оставляет все строки (быстрее). Колонки должны совпадать по числу и типам.

## Индексы

### 🟡 Вопрос: Что такое индекс? Зачем нужен?

Структура данных (обычно **B-дерево**), ускоряющая поиск/сортировку, как алфавитный указатель в книге. Ускоряет SELECT/WHERE/JOIN/ORDER BY, но **замедляет INSERT/UPDATE/DELETE** (индекс надо перестраивать) и занимает место.

### 🟡 Вопрос: Когда индекс не нужен / вреден?

- На маленьких таблицах.
- На колонках с низкой селективностью (мало уникальных значений, напр. пол).
- На часто изменяемых колонках.
- Когда запросов на запись намного больше, чем на чтение.

### 🔴 Вопрос: Какие виды индексов знаешь?

- **B-tree** — по умолчанию, для диапазонов и равенства.
- **Hash** — только точное равенство.
- **Составной (composite)** — по нескольким колонкам (важен порядок!).
- **Уникальный, частичный (partial), покрывающий (covering), GIN/GiST** (полнотекст, JSON, гео в PostgreSQL).
- **Кластерный** (определяет физический порядок строк) vs **некластерный**.

### 🔴 Вопрос: Как понять, что запрос медленный, и что делать?

Использовать `EXPLAIN ANALYZE` — посмотреть план запроса (есть ли Seq Scan вместо Index Scan, дорогие сортировки, nested loops). Действия: добавить индекс, переписать запрос, избегать функций на индексируемых колонках в WHERE, избегать `SELECT *`, денормализация, партиционирование.

## Транзакции и ACID

### 🟢 Вопрос: Что такое транзакция? Что такое ACID?

**Транзакция** — группа операций, выполняемых как единое целое (всё или ничего). Классика — перевод денег: списать с одного, зачислить другому.

**ACID:**
- **Atomicity (атомарность)** — всё или ничего, при сбое откат.
- **Consistency (согласованность)** — БД переходит из одного валидного состояния в другое (соблюдены ограничения).
- **Isolation (изолированность)** — параллельные транзакции не мешают друг другу.
- **Durability (долговечность)** — после commit данные сохранены даже при сбое.

### 🔴 Вопрос: Какие уровни изоляции транзакций есть?

От слабого к сильному (и какие аномалии устраняют):

| Уровень | Грязное чтение | Неповторяемое чтение | Фантомы |
|---|---|---|---|
| Read Uncommitted | возможно | возможно | возможно |
| Read Committed | нет | возможно | возможно |
| Repeatable Read | нет | нет | возможно |
| Serializable | нет | нет | нет |

**Аномалии:**
- **Грязное чтение** — читаем незакоммиченные чужие изменения.
- **Неповторяемое чтение** — перечитали строку, а она изменилась.
- **Фантомы** — повторный запрос вернул новые строки.

Чем выше изоляция, тем меньше параллелизм/производительность. По умолчанию в PostgreSQL — Read Committed.

### 🔴 Вопрос: Что такое CAP-теорема?

В распределённой системе нельзя одновременно гарантировать все три:
- **Consistency** — все узлы видят одни данные;
- **Availability** — система всегда отвечает;
- **Partition tolerance** — работает при разрыве сети.

При сетевом разделении (P неизбежно) выбираешь между **C** и **A**. Банковские системы чаще тяготеют к **CP** (целостность важнее доступности для денег).

### 🔴 Вопрос: Что такое BASE?

Альтернатива ACID для распределённых/NoSQL систем: **B**asically **A**vailable, **S**oft state, **E**ventual consistency (согласованность в конечном счёте). Жертвуем мгновенной согласованностью ради доступности и масштабирования.

## Чит-лист SQL

- Порядок: FROM→WHERE→GROUP BY→HAVING→SELECT→ORDER BY→LIMIT.
- WHERE до группировки, HAVING после.
- JOIN: INNER (пересечение), LEFT (все слева).
- Индекс ускоряет чтение, замедляет запись.
- Транзакция = ACID. Перевод денег — классический пример.
- Уровни изоляции: Read Committed (по умолчанию) → Serializable.
- M:N — через связующую таблицу.
