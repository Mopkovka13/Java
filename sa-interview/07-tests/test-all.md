## Ответы

| № | Ответ | Краткое пояснение |
|---|-------|-------------------|
| 1 | **B** | NFR — «насколько хорошо» (производительность, надёжность, безопасность) |
| 2 | **B** | Требование «быстрая» — не проверяемое; нужны числа |
| 3 | **B** | Классический формат: «Как [роль]...» |
| 4 | **C** | Gherkin (Given-When-Then) — формат критериев приёмки |
| 5 | **B** | DoR = готова к старту; DoD = готова к выпуску/закрытию |
| 6 | **C** | RICE = Reach × Impact × Confidence / Effort |
| 7 | **B** | БА — «зачем бизнесу»; СА — «как реализовать в системе» |
| 8 | **B** | Independent, Negotiable, Valuable, Estimable, Small, Testable |
| 9 | **B** | Pool = отдельный участник (организация, система) |
| 10 | **C** | AND-шлюз (параллельный) — все ветки выполняются одновременно |
| 11 | **B** | Sequence-диаграмма — обмен сообщениями во времени |
| 12 | **B** | Композиция — сильная (часть не живёт без целого); агрегация — слабее |
| 13 | **B** | C4 — иерархическое описание архитектуры на 4 уровнях |
| 14 | **B** | 1:N (один клиент — много заказов) |
| 15 | **B** | FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY |
| 16 | **B** | WHERE — до GROUP BY (строки); HAVING — после (группы с агрегатами) |
| 17 | **C** | LEFT JOIN + `WHERE o.id IS NULL` = нет совпадений в orders |
| 18 | **B** | DENSE_RANK не пропускает номера при равных значениях |
| 19 | **B** | `SUM(...) OVER (PARTITION BY ... ORDER BY ...)` — оконная функция |
| 20 | **B** | NULL != UNKNOWN — любое сравнение с NULL даёт UNKNOWN |
| 21 | **B** | Индекс ускоряет чтение, замедляет запись |
| 22 | **D** | Serializable — единственный уровень без фантомов |
| 23 | **B** | CAP: при Partition выбираем C или A |
| 24 | **B** | Outbox = атомарно данные + событие в БД → потом публикация |
| 25 | **B** | Saga = локальные транзакции + компенсации при распределённых операциях |
| 26 | **A** | CQRS = разные модели для записи (Command) и чтения (Query) |
| 27 | **B** | API Gateway = маршрутизация + аутентификация + rate limiting |
| 28 | **B** | Деньги: CP, согласованность важнее (RPO ≈ 0) |
| 29 | **B** | Шардирование = горизонтальное разбиение данных по ключу |
| 30 | **B** | Circuit Breaker открывается при превышении порога ошибок |
| 31 | **B** | В Kafka порядок гарантирован только внутри партиции |
| 32 | **B** | Exactly once = idempotent producer + транзакции |
| 33 | **B** | Kafka хранит как лог (can replay); RabbitMQ удаляет после ack |
| 34 | **B** | DLQ = «карантин» для необработанных сообщений |
