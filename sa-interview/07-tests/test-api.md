## Ответы

| № | Ответ | Пояснение |
|---|-------|-----------|
| 1 | **C** | PATCH — частичное обновление; PUT — полная замена |
| 2 | **B** | 201 Created — новый ресурс создан; 200 — для существующего |
| 3 | **B** | 403 — аутентифицирован, но нет прав |
| 4 | **C** | 401 — не аутентифицирован (нет/невалидный токен) |
| 5 | **B** | GET (safe + idempotent), PUT, DELETE — идемпотентны; POST — нет |
| 6 | **B** | DELETE несуществующего → 404 (хотя некоторые возвращают 204 — зависит от соглашения) |
| 7 | **C** | Глагол `getOrder` в URL + POST вместо GET — нарушает REST |
| 8 | **B** | Stateless — каждый запрос самодостаточен |
| 9 | **B** | Keyset не деградирует на больших данных в отличие от offset |
| 10 | **D** | GET (не POST), глагол в URL, параметры в query (не в теле), имя поля `sum` |
| 11 | **B** | Idempotency-Key защищает от двойного списания при retry |
| 12 | **C** | Возвращаем прежний результат с 200 OK — операция «уже выполнена» |
| 13 | **B** | OpenAPI = стандарт описания REST API |
| 14 | **C** | Асинхрон через брокер — платёж не ждёт уведомления; развязка |
| 15 | **B** | gRPC — бинарный Protobuf, HTTP/2, low latency, строгий контракт |
| 16 | **C** | ФНС принимает файлы, не JSON-API; SFTP/batch — стандарт для госсистем |
| 17 | **B** | Webhook — push-модель (шлюз → нам); polling — pull (мы → шлюз) |
| 18 | **B** | Сначала верифицировать подпись — иначе любой может подделать webhook |
| 19 | **C** | Circuit Breaker — «предохранитель», отключает вызовы при серии ошибок |
| 20 | **B** | Exponential backoff — нарастающая пауза (1с, 2с, 4с...) |
| 21 | **B** | Шлюз повторит webhook — поэтому нужна идемпотентность обработки |
| 22 | **C** | DLQ — очередь для «мёртвых» (необработанных) сообщений |
| 23 | **C** | Переименование обязательного поля — breaking change; добавление необязательного — нет |
| 24 | **C** | `deprecated: true` в OpenAPI + заголовки Deprecation/Sunset |
| 25 | **B** | WSDL — строгий XML-контракт SOAP; OpenAPI — описание REST |
